<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → FastAPI path params | Untrusted `{name}` path segment crosses here on GET and DELETE |
| FastAPI handler → local disk | Server reads/unlinks/renames files in data/frames and data/songs based on the (validated) name |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Tampering | GET/DELETE `{name}` path traversal (e.g. `../../etc/passwd`) | mitigate | `FPath(pattern=r"^frame_\d+$")` / `^song_\d+$` validated by Pydantic BEFORE the handler runs; any `/`, `..`, or non-digit char yields 422 and the handler never builds a path. This is the server's only traversal defense — covered by TestPathTraversal |
| T-02-06 | Information Disclosure | ETag derived from content vs metadata | mitigate | ETag = MD5 of file content (cache fingerprint, not a security hash — RESEARCH V6). MD5 is intentional here; no secret is hashed, so collision/preimage weakness is irrelevant |
| T-02-07 | Tampering / Integrity | reorder-on-delete clobbering files | mitigate | Ascending `range(idx+1, total)` rename order guarantees no source file is overwritten before it is moved (RESEARCH Pitfall 3); delete + reorder runs inside `_manifest_lock` with atomic manifest rewrite |
| T-02-08 | Repudiation / Integrity | manifest drift after delete | mitigate | manifest frames/songs lists are rebuilt from the new slot count, not patched via string replacement, preventing state drift between disk and manifest |
</threat_model>
